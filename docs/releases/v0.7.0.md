# v0.7.0

**Release Date:** 2026-09-07

## Overview

This release adds the **generic `sql` connector** — the first Tier-1 connector shipped in the engine core (ADR-0002): any PostgreSQL, MySQL/Dolt, or SQLite database becomes a queryable analytics source through configuration alone, no application code required. It also updates the `systemforge` dependency to the `plexusone` module path.

## Highlights

- **Built-in `sql` connector** — registered as `sql`, ships with stock `dashforge-server`; introspects the schema (`INFORMATION_SCHEMA` for Postgres/MySQL, `sqlite_master` + `PRAGMA` for SQLite) and maps native column types to `number`/`date`/`dimension` field roles
- **ADR-0002: connector extensibility tiers** — the four-tier model for connecting to sources DashForge doesn't own: generic protocol drivers in core (`sql`), first-party composed Go connectors, a published Analytics Provider HTTP/JSON contract, and a metadata-table convention enriching the SQL tier
- **ADR-0004: embedding contract** — embed the UI, not the tables; builds on ADR-0001 (domain-free engine), ADR-0002 (connector tiers), and compass ADR-0001

## Added

### The Built-In `sql` Connector

Any PostgreSQL, MySQL/Dolt, or SQLite database becomes a source through configuration alone:

```json
{
  "id": "warehouse",
  "name": "Warehouse",
  "connector": "sql",
  "dsnRef": "env://DASHFORGE_WAREHOUSE_DSN",
  "enabled": true
}
```

The dialect is selected from the resolved DSN's form — `postgres://`/`postgresql://` for PostgreSQL, `mysql://` or a go-sql-driver DSN for MySQL/Dolt, `sqlite://`/`file:`/a `.db`/`.sqlite` path for SQLite. Query execution is read-only: a single leading `SELECT`, scanned directly into catalog rows. See [Analytics Catalog](../analytics-catalog.md#the-built-in-sql-connector) for the full reference.

## Fixed

- Updated `systemforge` imports (authz/multiapp/session call sites) to `github.com/plexusone/systemforge` and bumped to v0.10.0. Also fixed the `authzed/cel-go` exclude: `spicedb` v1.56.1's `caveats/replacer` now expects the post-v0.30.0 two-return-value `cel.NewStaticOptimizer` signature, so excluding v0.32.0 alongside v0.30.0 was forcing MVS down to the incompatible v0.20.2 and breaking the build.

## Dependencies

- Bump `github.com/go-sql-driver/mysql` from 1.10.0 to 1.10.1.
